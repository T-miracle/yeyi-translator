# 页译：Chrome / Edge 网页翻译插件

页译使用你自己的 **DeepSeek 或 OpenAI API Key** 翻译网页，支持原文与译文逐段对照，也支持用译文替换原文。

**当前源码版本：1.3.8（缓存修复测试包）。** Releases 已发布安装包仍为 **1.3.7**。普通用户下载安装包即可使用，不需要安装 Node.js。

[下载安装包](https://github.com/T-miracle/yeyi-translator/releases/latest) · [查看全部版本](https://github.com/T-miracle/yeyi-translator/releases)

## 能做什么

| 功能             | 使用效果                                                   |
| ---------------- | ---------------------------------------------------------- |
| 整页翻译         | 按页面阅读顺序，从上到下逐批翻译已加载的文字               |
| 换行双语         | 每段原文下方显示译文，方便对照阅读                         |
| 替换原文         | 在原来的位置显示译文，尽量保留链接、加粗和页面排版         |
| 一键恢复原文     | 撤回插件的翻译改动，恢复阅读原文                           |
| 轻量悬浮按钮     | 两个小圆形按钮分别用于翻译和设置，圆环直接展示翻译进度     |
| 快捷翻译         | 默认 Ctrl+X 切换翻译与恢复原文，可在设置中修改或停用       |
| 隐藏悬浮球       | 默认不隐藏；开启隐藏后，翻译时显示，恢复原文后自动隐藏     |
| 中文自动跳过     | 中文原文在本地保留，混排中的外文可参考中文上下文再翻译     |
| 动态内容翻译     | 翻译开启后，继续处理滚动加载、展开或更新的文字             |
| 只翻译可视页面   | 默认关闭；开启后优先处理可视段落，并向上下各预翻译 10 句   |
| Discord 兼容     | 自动排除消息作者、回复作者和成员昵称，保留聊天正文翻译     |
| 持久翻译缓存     | 默认关闭；开启后跨页面、刷新和重启复用，支持导入导出与清理 |
| 人名字典         | 固定角色译名，支持增删改、搜索及 AiNiee JSON 导入导出      |
| 自动获取模型     | 填入 Key 后自动获取可用模型，也可以手动填写模型 ID         |
| 指定网站自动翻译 | 为常用网站开启自动翻译，其他网站保持手动                   |
| 两家服务分别配置 | DeepSeek 和 OpenAI 各自保存 Key、模型及 API 地址           |
| 兼容自定义接口   | 可以修改 API 地址和模型，连接兼容 Chat Completions 的服务  |

原文语言自动识别，默认译为简体中文。还可选择繁体中文、英语、日语、韩语、法语、德语、西班牙语、葡萄牙语、俄语、阿拉伯语、意大利语、越南语和泰语。

## 第一步：下载安装包

1. 打开 [最新版本下载页面](https://github.com/T-miracle/yeyi-translator/releases/latest)。
2. 在页面的 **Assets（资源）** 中下载 `yeyi-translator-1.3.7.zip`。
3. 把 ZIP 解压到一个准备长期保留的文件夹。
4. 打开解压后的文件夹，确认里面能直接看到 **`manifest.json`**。

浏览器安装时选择这个文件夹。安装后请保留文件夹，因为浏览器会继续从这里读取插件文件。

GitHub 页面中的 **Source code（源码）** 压缩包用于开发，需要构建后才能加载。直接安装请使用上面的 `yeyi-translator-版本号.zip` 文件。

## 第二步：安装到浏览器

Chrome 和 Edge 使用同一个安装包，分别在各自的扩展管理页加载。

| 浏览器         | 在地址栏输入          |
| -------------- | --------------------- |
| Chrome         | `chrome://extensions` |
| Microsoft Edge | `edge://extensions`   |

进入对应页面后：

1. 打开 **开发者模式**。
2. 点击 **加载已解压的扩展程序**。Edge 中也可能显示为“加载解压缩的扩展”。
3. 选择第一步中包含 `manifest.json` 的文件夹。
4. 在浏览器的扩展菜单中找到“页译”，将它固定到工具栏，方便后续使用。

首次安装完成后，刷新一下准备翻译的网页。

## 第三步：填写 Key 并选择模型

点击工具栏中的“页译”，再点击设置按钮，进入插件设置页。

### 使用 DeepSeek

1. 在 [DeepSeek 平台](https://platform.deepseek.com/api_keys) 创建自己的 API Key。
2. 在插件设置的 **DeepSeek** 卡片中填写 Key。
3. 等待约 **0.75 秒**，插件会自动获取模型列表。
4. 从下拉框选择模型，例如 `deepseek-flash`。
5. 选择 **使用此服务**，可先点击 **测试连接**，最后点击 **保存设置**。

### 使用 OpenAI

1. 在 [OpenAI 平台](https://platform.openai.com/api-keys) 创建自己的 API Key。
2. 在插件设置的 **OpenAI** 卡片中填写 Key。
3. 等待自动获取模型，从列表选择支持文本对话的模型，例如 `gpt-4.1-mini`。
4. 选择 **使用此服务**，可先点击 **测试连接**，最后点击 **保存设置**。

可以同时保存两家服务的配置，再在工具栏弹窗中切换当前服务。插件不会自动替你切换到另一家服务。

### 默认地址和模型

| 服务     | 默认 API 地址（Base URL）   | 默认模型 ID      |
| -------- | --------------------------- | ---------------- |
| DeepSeek | `https://api.deepseek.com`  | `deepseek-flash` |
| OpenAI   | `https://api.openai.com/v1` | `gpt-4.1-mini`   |

以上默认值于 2026-10-15 核对。具体可用模型以你的账户权限和自动获取的结果为准。模型列表中可能包含不支持文本对话的模型，请按服务实际支持情况选择。

**模型展示名和模型 ID 可能不同。** 例如 `DeepSeek-V4.1-Flash` 是版本展示名，对应的 API ID 是 `deepseek-flash`。从下拉框选择时，插件会使用真实 ID 发起请求。已有输入只有在唯一匹配接口返回的名称或 ID 时，才会被改为真实 ID，并提示保存设置。

### 选择推理级别

每个服务卡片的“模型”下方都有 **推理级别**，两家服务分别保存。DeepSeek 另有独立的 **思考模式**，测试连接使用与网页翻译相同的开关和级别。修改后点击“保存设置”，实际生效参数发生变化时，正在翻译的页面才会重新翻译。

- **DeepSeek 思考模式**：可选关闭、开启、接口默认。是否思考只由此设置决定；接口默认由服务端决定。
- **DeepSeek 推理级别**：可选接口默认、低、高、最高，仅在思考模式选择“开启”时发送。关闭时可以预选级别，调高也不会开启思考、重译或使缓存失效。[DeepSeek 官方参数说明](https://api-docs.deepseek.com/api/create-chat-completion/)
- **OpenAI／兼容接口**：可选接口默认、关闭思考、极低、低、中、高、极高、最高。模型支持的档位不同，非推理模型请选择接口默认；不支持所选档位时会保留接口错误，不会自动降档。[OpenAI 官方参数说明](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)

推理级别控制思考开启后的强度，更高档位通常增加耗时和用量。升级保留原行为：从未设置过推理的 DeepSeek 官方配置继续关闭；上一版选择的“关闭思考”迁移为关闭，已选择低、高或最高的配置迁移为开启并保留级别，接口默认保持接口默认。迁移只补齐读取结果，不主动重写本机数据。不同的实际请求参数分别复用缓存，旧译文和人名字典保留，切回原模式与级别可继续命中原缓存。

更新扩展文件后，还需要在扩展管理页点击 **重新加载**。仅刷新设置页时，旧后台可能仍在运行，无法保存新增字段；设置页会兼容显示旧配置并提示 **重新加载扩展**，更新完成前禁止保存和连接测试，避免误报成功。完成重新加载后再次打开设置即可，已有 Key、缓存和字典保留。

### 使用代理或其他兼容接口

1. 先把对应服务的 **Base URL** 改为服务方提供的 API 地址。
2. 再填写这个服务的 Key，等待自动获取模型。
3. 如果对方没有提供模型列表，选择或保留 **手动输入模型 ID**，填写服务方给出的 ID。
4. 测试连接并保存设置。

修改 Key 或地址后会重新自动获取模型；“重新获取”按钮可手动刷新。获取失败时，原来的模型配置会保留，你仍可手动填写。

获取模型只请求模型列表，不发送网页内容，也不会启动翻译。**测试连接会发送一条短文本；测试和网页翻译均可能产生 API 费用，费用由你配置的服务收取。**

## 如何翻译网页

1. 打开普通网页，点击右下角紫色圆形 **译** 按钮，直接开始翻译。
2. 按钮外圈显示翻译进度；再次点击同一个按钮，恢复原文。
3. 点击旁边较小的齿轮圆形按钮，可调整目标语言、翻译服务、显示模式和本站自动翻译。

常用设置中还可暂停、继续或重试失败部分，按 Esc 或点击面板外部即可收起。API Key、模型和接口地址通过 **完整设置** 配置。浏览器工具栏中的“页译”弹窗仍可使用。

已经是中文的段落（包括其中的品牌名、链接和数字）直接保留，不单独调用翻译 API。启用人名字典后，先在本机应用约定译名，包括纯汉字人名及中文句子中的人名，其余中文仍原样保留。混合段落只请求外文翻译；需要时附带少量中文作为上下文，这部分上下文仍计入输入 token。

待翻译内容按阅读顺序合批，每批最多 18 个文本片段、约 4,800 字符（含上下文），满批立即发送；不足一批时聚合 200 毫秒内新增的内容，再一起请求，避免动态页面逐条调用。发送前会重新检查页面和缓存，仅未命中的内容占用请求。失败片段转入独立重试队列，后面的正常待译内容优先处理，不等待失败项的退避计时或反复补译。

### 日语论坛翻译

发送翻译请求前，插件在本机按段落检查平假名、片假名及半角片假名，识别为日语时自动使用专用提示词，无需新增开关或额外的语言识别 API 请求。中英日混排时，只对识别出的日语片段应用此规则，不根据网页的 `lang` 标签把整页当作日语。

日语提示词要求准确理解省略、敬语、语气、否定和论坛常用表达，译成通俗自然的目标语言；日译中使用符合中文论坛交流习惯的口语，不照搬日语语序，也不硬塞流行梗、扩大情绪或补充事实。人名字典仍优先，加粗、链接等内联节点中的纯汉字沿用整段的日语判断，不再被当成中文跳过。纯汉字、没有假名或日语段落依据的短句无法可靠区分中日文，继续使用既有保留与翻译规则。

此功能不改变思考模式或推理档位。新日语译文使用独立的提示词版本缓存，避免继续显示旧风格；原有日语缓存、其他语言缓存、Key、设置和字典都保留，不清空或覆盖存档。开启持久缓存时，首次遇到旧日语内容会重新翻译并增加对应的新缓存条目。

### 两种翻译模式

- **换行双语**：原文保留，译文显示在每段原文下方。
- **替换原文**：原文位置显示译文，尽量保留链接、按钮行为及原有格式。

已有译文时，切换两种模式会直接复用译文，不重复请求 API。文字长度发生变化时，网页可能重新换行。

### 中文译文字体优化

在完整设置的 **阅读偏好 → 中文译文字体优化** 中开启并保存。此功能默认关闭，已有用户升级后也保持关闭。保存后立即更新当前页面已有译文，无需重新调用翻译 API；替换原文和双语模式都支持，暂停的译文也可调整。

开启后，简体中文优先使用本机的 **微软雅黑**，再依次尝试苹方、思源黑体等中文字体；繁体中文优先使用 **微软正黑体**及对应繁体字体。只调整译文现有文字容器的 `font-family`，保留原有字号、字重、颜色、行距和 DOM 层级，避免新增文字包裹干扰动态网站。含图标私用字形的容器及未参与翻译的独立中文段落保持原样。字体覆盖范围和字体本身的字面大小仍取决于本机安装情况，少数字符可能仍需回退；不额外下载字体。

关闭优化、恢复原文或切换显示模式时，会恢复原字体。网页在翻译期间自行修改的字体和其他样式会保留。此选项仅改变显示，不改变翻译缓存的键，不清理缓存、人名字典或 Key，也不会把字体现状或备份写入存档。

X 等动态页面重新写回相同原文时，会直接重绘已完成的译文，避免进度显示完成却仍看到日文；同页已有结果继续复用，不重复请求。

### 只翻译可视页面与 Discord

在完整设置的“阅读偏好”中打开 **只翻译可视页面**。此开关仅保留在完整设置，默认关闭；关闭时仍按文档顺序翻译所有已加载且未隐藏的段落。

开启后，优先翻译当前视口内可见的段落，并在同一滚动区域向上、向下各预翻译 10 句。滚动、展开内容或调整窗口后，窗口自动跟随；向上滚动时继续补充上方 10 句，不重复请求已完成的内容。按完整段落保留排版，边界段落可能超过剩余句数。超出预翻译窗口、页面隐藏或被永久裁剪的内容不请求 API；屏幕外的独立滚动列表也不会被当作其他区域的上下文。已有译文在滚出视口后保留，暂停翻译会停止监测。

Discord 会自动排除消息作者、回复作者、成员显示名和昵称，不将这些姓名节点提交给翻译服务。规则使用语义 ID 和类名前缀，兼容页面类名哈希变化，也适用于具有相同页面结构的本地 HTML 快照。聊天区域的内部滚动同样会触发新内容翻译。

消息列表滚动期间暂缓写入译文和字体，已返回的网络结果与缓存结果照常保存；滚动停稳约 **180 毫秒** 后重新核对当前消息并统一显示，避免译文重排或位置补偿打断平滑、惯性滚动。此行为同时适用于替换原文和双语模式，不锁定消息高度，不裁剪文字，也不修改字号。停稳时仅补偿此次写入造成的实际位移，已在底部时保留网站跟随行为。

### 持久缓存、容量提醒与导入导出

在完整设置的“翻译缓存”中打开 **启用持久翻译缓存** 并保存。此选项默认关闭，关闭时维持原有的当前页面内存复用；开启后，已完成的译文还会保存到本机，刷新、关闭页面或重启浏览器后可以继续复用。

页面文字在进入待翻译队列之前先匹配缓存。命中后优先显示译文，不占用待翻译批次，不等待同页其他 API 请求；仅未命中的内容排队。普通页面命中后立即显示，Discord 消息列表在滚动停稳后显示。新出现的内容和预翻译窗口也遵循这个顺序。缓存查询是只读操作，缓存格式及现有条目保持兼容。

- **容量提醒阈值**：默认 **512 MB**，可在设置中调整。大小由浏览器实际统计，超过阈值显示感叹号，仍然继续保存，不自动淘汰或删除条目。容量单位按 1024 换算。
- **导出缓存**：下载带格式版本的 JSON 文件，包含原文摘要与译文，不含 API Key、服务配置或站点名单。译文仍可能包含私人内容，请妥善保管和分享。
- **导入缓存**：先校验完整文件，再分批合并新条目。重复条目保留本机已有译文，不覆盖旧结果；超过容量提醒阈值也可以导入。若本机存储故障导致中止，界面显示已导入数量，原有缓存保留。
- **清空缓存**：清理持久缓存和已打开页面的复用缓存，保留 Key、设置、当前可阅读的译文及恢复原文记录。清理前已经发出的请求不会把旧结果重新写入缓存。

缓存按服务、规范化的接口地址、模型、目标语言、原文分片及上下文区分，不依赖 API Key、临时段落 ID 或双语/替换模式。相同配置和文本结构下，导入其他浏览器或设备导出的缓存即可复用；修改接口、模型、语言或页面分片结构后可能需要重新翻译。

关闭缓存只停止持久缓存的读取和写入，保留已存条目，重新开启后可以继续使用。缓存使用独立存储空间；磁盘写入失败不会使翻译失败或删除已有数据，设置页会显示提示。导入导出支持超过 64 MiB 的文件。

### 快捷翻译与隐藏悬浮球

在普通网页按 **Ctrl+X**，即可像点击悬浮球一样开启翻译，再按一次恢复原文并关闭翻译。快捷键沿用当前的双语或替换模式，子框架中也可触发整页操作。

在完整设置的“阅读偏好 → 快捷翻译”中，点击输入框并按下新组合，再保存即可立即生效；支持 Ctrl、Alt 或 Meta 搭配字母、数字或 F1～F12，可附加 Shift。也可以停用或恢复默认快捷键。输入框与富文本编辑器中保留剪切等操作，长按不会反复切换。

**隐藏悬浮球**默认关闭。开启后，未翻译时隐藏悬浮球；通过快捷键、工具栏或自动翻译启动后显示，恢复原文后重新隐藏。暂停时保留译文和悬浮球，便于继续翻译。沿用已有的悬浮按钮设置字段，保留 API Key、网站名单和缓存。

### 人名字典与 AiNiee 导入导出

在完整设置的 **人名字典** 中添加或导入角色名。字典操作即时保存，无需再点击底部的“保存设置”。可搜索原文、译文和描述，再编辑或删除单条人名；关闭字典保留全部数据。

导入导出采用 [AiNiee AI 术语表](https://github.com/NEKOparapa/AiNiee/wiki/%E8%A1%A8%E6%A0%BC%E2%80%90AI%E6%9C%AF%E8%AF%AD%E8%A1%A8%E4%BB%8B%E7%BB%8D) 的 JSON 列表格式：每项包含 `src`（原文）、`dst`（约定译名）、可选的 `info`（描述）。导出文件可直接导入 AiNiee。支持其 `regex: false` 的普通人名条目；启用正则的条目会明确报错，避免不同正则引擎导致误匹配。当前仅支持 JSON，单份文件最多 8 MB、10000 条。

- **导入合并**：先完整校验文件，再一次性合并；相同原文不区分大小写，本机已有条目优先保留，文件中的重复条目保留第一条。坏文件不会清空或部分覆盖已有数据，存储失败会提示错误。空译文可留作待补充条目，不参与翻译。
- **译名生效**：人名字典优先于中文跳过规则；纯汉字人名及保留的中文片段在本机按最长匹配替换，保留未命中的文字、标点和首尾空白，不调用 API。独立的人名标签同样直接使用约定译名；其余外文正文仅把本次命中的人名和描述作为字典提示发送给 AI，其中的译名遵循情况仍取决于所选模型。约定译名适用于所有目标语言。
- **页面与缓存**：修改字典后，翻译中的页面自动按新字典更新。缓存按字典摘要隔离；旧缓存继续保留，停用字典可复用原有配置的缓存。多设置页同时编辑同一条目会检测冲突，拒绝过期覆盖。
- **数据保存**：字典与接口设置、译文缓存分别保存在本机。保存设置或清理缓存不删除字典。导出只包含人名、译文和描述，不包含 Key 或接口配置；卸载扩展仍会移除其本机数据，请按需导出备份。

本地字典及提取来源请放在已被 Git 忽略的 `user-data/` 目录；它们属于用户数据，不随源码提交或构建产物分发。

### 暂停、继续、恢复和重试

- **暂停翻译**：停止后续请求和新内容监测，保留已经完成的译文。
- **继续翻译**：复用当前页面中的结果，继续处理未完成部分；暂停前的自动重试次数保持不变。
- **恢复原文**：停止翻译并撤回插件改动。网站在翻译期间更新的文字会保留为网站的最新内容。
- **重试失败部分**：在悬浮设置面板或工具栏弹窗中点击对应按钮，只重新请求已停止重试的失败部分，并为这些片段重新计数。

模型省略表情、标点或纯数字片段时，会保留原字符。批量译文缺项、格式错误或被截断时，失败片段转入重试队列，后续逐段请求；包含多份内联文字的格式失败段落，会在下一轮携带整段上下文逐节点补译，完成后仍按原段落显示和保存缓存。

页面翻译中的临时网络故障、限流、服务错误和格式错误，首次失败后最多自动重试 **3 次**（含首次请求最多 4 轮），依次等待 1、2、4 秒；正常待译内容优先，后台不会叠加另一套重试。耗尽次数后保留原文，可手动重试。暂停、继续及重新扫描不会重置自动重试次数。Key 无效、额度不足或模型配置错误时，会提示原因并停止当前页面帧中的后续任务。

### 为常用网站开启自动翻译

在悬浮设置面板中打开 **本站自动翻译**，或在工具栏弹窗中打开 **此网站自动翻译**。之后重新进入这个网站时，就会自动开始翻译。

也可以在设置页的“自动翻译网站”中每行填写一个主机名，例如：

```text
docs.example.com
news.example.com
```

这里只精确匹配填写的主机名。`example.com` 不会同时包含 `docs.example.com`；需要分别添加。自动翻译会把页面文字发送到当前选择的 API 服务。

## 常见问题

### 找不到 `manifest.json`，或者浏览器提示无法加载

请先解压插件 ZIP，再选择包含 `manifest.json` 的文件夹。如果下载的是 GitHub 的源码压缩包，请按下文“从源码构建”操作，或重新下载 Release 中的插件安装包。

### 填入 Key 后没有获取到模型

检查 Key 是否有效、Base URL 是否正确、网络能否访问这个服务，再点击“重新获取”。部分兼容服务没有提供模型列表，可以手动填写模型 ID 后测试连接。

### 测试连接提示 HTTP 400

先看界面显示的具体服务错误和参数。常见原因包括模型 ID 填写错误，或者服务不支持当前请求参数。

对于 DeepSeek，请从自动获取的列表中选择模型 ID，例如 `deepseek-flash`，然后测试并保存。不要直接把版本展示名当作模型 ID。

### 提示 Key 无效、额度不足或请求过于频繁

- **Key 无效**：检查是否填错服务、Key 是否完整、是否已被撤销。
- **额度不足**：到对应服务平台查看可用额度或余额。
- **请求过于频繁**：稍后重试，或减少同时翻译的网页数量。

### 为什么有些文字没有翻译

当前版本处理普通网页中已经加载、可读取的文字，包括主文档和有访问权限的 HTTP/HTTPS iframe。

以下内容不在当前支持范围内：

- 图片、Canvas、SVG 中的文字和 OCR 识别。
- 浏览器内置 PDF 查看器、扫描 PDF。
- 浏览器内部页、扩展管理页、扩展商店页。
- 输入框、文本域、可编辑区域和代码块。
- 网站标记为 `translate="no"`、`.notranslate` 的区域，以及隐藏内容。
- 组件的 Shadow DOM 内部文字。

尚未滚动加载到页面中的内容，需要先滚动加载。插件会继续翻译新出现的文字，但不会自动滚动、展开折叠区域或点击“加载更多”。

### 为什么刷新后会重新翻译

默认关闭持久缓存，因此刷新或关闭页面后会重新请求 API。在完整设置中开启“启用持久翻译缓存”后，相同接口、模型、目标语言和原文结构下可直接复用已保存的结果。

### 如何更新插件并保留 Key

1. 下载新版插件安装包并解压。
2. 用新版文件覆盖原来加载的插件文件夹。
3. 在扩展管理页找到“页译”，点击 **重新加载**。
4. 刷新设置页和待翻译的网页。

继续使用原来的插件目录，并重新加载同一个扩展，可以保留已有的 Key、设置、翻译缓存和人名字典。不要先移除旧扩展，也不要换一个目录重新加载成第二个扩展。

## 数据保存和访问权限

- Key、服务配置、阅读偏好和自动翻译网站名单仅保存在浏览器本机扩展存储中，不使用浏览器同步。
- 存储访问限制为扩展可信页面和后台，网页内容脚本收到的配置不包含 Key。
- 默认只在当前页面内存中保存原文与译文。主动开启缓存后，仅将原文摘要与译文写入独立的本机持久缓存，不持久化完整原文；导入导出不包含 Key 或设置。
- 网页文字直接发往你配置的 API。页译没有中转服务器和遥测，也不会记录 Key、请求原文或原始响应。
- 界面中的服务错误经过脱敏和长度限制。
- 要移除 Key，清空对应输入框并保存。卸载扩展会移除其本机设置。

扩展需要的权限及用途：

| 权限                     | 用途                                                                 |
| ------------------------ | -------------------------------------------------------------------- |
| `storage`                | 保存本机设置与用户主动开启的译文缓存                                 |
| `unlimitedStorage`       | 允许缓存超过浏览器默认配额，实现超过提醒阈值后继续保存               |
| `activeTab`、`scripting` | 对当前网页执行操作，给安装前已打开的网页补充脚本                     |
| HTTP/HTTPS 网站访问      | 显示网页入口、按站点自动翻译、处理可访问的网页帧，以及连接配置的 API |

默认使用手动翻译。自动翻译只对你主动添加的网站生效。

## 自定义 API 的兼容要求

以下内容供对接代理服务或本机服务时参考：

- 翻译接口兼容 `POST /chat/completions`，使用 Bearer Key、`messages`、`stream` 和 `response_format: {"type":"json_object"}`。
- 成功响应通过标准 `choices[].delta.content` 或 `choices[].message.content` 返回译文。支持 SSE 流式响应和完整 JSON 响应。
- 自动获取模型使用 `GET /models`，从响应的 `data` 数组读取模型 `id`，以及可选的展示名 `name`。
- Base URL 可以是 API 根路径、带 `/v1` 的根路径，或完整的 `/chat/completions` 端点。完整端点不会重复拼接；其他地址会追加 `/chat/completions`，不会自动增删 `/v1`。
- API 地址使用 HTTPS。本机 `http://localhost`、`http://127.0.0.1` 和 IPv6 回环地址可以使用 HTTP。
- 扩展最低要求为 Chromium 主版本 120，使用 Manifest V3。

官方接口参考：

- [OpenAI Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)
- [OpenAI 模型列表](https://developers.openai.com/api/reference/resources/models/methods/list)
- [DeepSeek 首次 API 调用与模型名称](https://api-docs.deepseek.com/guides/codex)
- [DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)
- [DeepSeek 模型列表](https://api-docs.deepseek.com/api/list-models/)
